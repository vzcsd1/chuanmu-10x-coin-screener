# 追溯机制：一个想法在实验前后怎么「回头找思路」

> 2026-10-21｜回答用户问题：「一个想法在实验前后，有没有追溯曾经遗弃或者已经完成的步骤来找思路。
> 这个项目目前有做过这事吗？我认为这对项目的上限以及实操节省时间和资源很重要。」
>
> 配套产物：`research_ledger.json`（数据源）· `tools/ledger.py`（六个命令）·
> `research_committee/想法台账.md`（人话版，生成物，不要手改）

---

## 0. 一句话回答

**做过，但只是一次性的手工行为，从来没成机制。** 靠的是「某个人恰好想起来去翻」，
想起来就翻到了，想不起来就一直挂着——所以它现在既不能保证上限，也谈不上省时间。

本轮把它做成了机制：**一份按想法索引的台账 + 一个开实验前必查的命令 + 一条「做完实验必须回扫」的纪律**。

---

## 1. 现在项目里「追溯」的痕迹：有五处，但每处都缺一块

先说公道话——这个项目不是完全没做追溯，是**做了五种，每种只覆盖一部分**：

| 已有的东西 | 能回答什么 | 缺什么 |
|---|---|---|
| `TODO.md` 末尾「已作废、不要再做」表 | 哪些方案被否了 | 只说「不要再做」，**不说为什么、什么条件下能重开** |
| `KNOWLEDGE.md` §6.2「误区 1–14」 | 踩过哪些坑 | 是**教训清单**，不是想法索引；查它得先知道坑叫什么 |
| `REASONING.md` 每条的「何时失效」 | 某个结论什么时候不成立 | **只覆盖「结论」，不覆盖「想法」**；且没和「要不要重测」挂钩 |
| `DONE.md` | 做完过什么 | 按任务写，**按时间排，不按想法排**；同一想法做过三次会写成三条 |
| `reports/`、`research_committee/` 各份报告 | 细节 | 散在 30+ 份文档里，**grep 的前提是你记得住当时用的词** |

**最要命的是最后一行**。举例：A27 那轮我想知道「M30 动量加速度测过没有」，
`grep 动量` 能搜到，但如果当初我把它写成「价格二阶导」呢？搜不到就等于没做过。

**这不是假设，是已经付过的学费。**

## 2. 已经付掉的学费（三个真实例子）

### 例子 1：A20 的 15 条规则，5 条一折都没跑出来

A20 是「否决制实验」，跑了 15 条入池规则。当时写进 `KNOWLEDGE.md` 的结论是
「15 种规则全试过、0 个胜出」。

A27 那轮我手工打开 `results/gate_folds.csv` 一条一条对，才发现：
**只有 7 条是四折齐全可比的，3 条折数不全，剩下 5 条一折都没跑出来。**

也就是说，那句「15 种全试过」里，有三分之一根本没试。
如果那轮没去翻这个 csv——**这个错误会一直挂在 KNOWLEDGE 里，被后面每一轮当作既定事实引用**。

这次是运气好：我恰好怀疑了它。

### 例子 2：M30 被用错裁判判死

M30（动量加速度）在 A22 被判「换皮（与已有变量重复）」，理由是它和 `score` 的 Spearman 相关 0.5 以上。
但 A22 用的**标签是爆拉标签**。A27 换收益标签重算，发现它池内对 7 日净收益 **+0.129**——
方向是对的，只是爆拉率没提升。

**同一个东西，换一个裁判，结论相反。** 这条判决在 KNOWLEDGE 里躺了一整天没人动。

### 例子 3：M05 被低估成「换皮」，实际是「有害」

M05（大户散户剪刀差）判死理由是「与 `ls_top` 相关 0.56，是换皮」。
A27 一看池内收益相关 **−0.255**——它不是没用，是**反着用**。
「换皮」和「有害」是两种完全不同的死法，前者说明白测了，后者说明**它有信息只是方向反了**。

## 3. 缺的到底是什么：三个具体缺口

把上面三件事拆开看，缺的不是「文档」，是三样具体的东西：

**缺口一：没有「按想法索引」。**
文档是按时间（DONE）、按主题（KNOWLEDGE）、按任务（reports）组织的。
**没有一个地方能让你输入「动量」两个字，就吐出「做过、判死、因为换皮、除非找到正交表达」这一整行。**

**缺口二：判决里没有「为什么停」和「什么条件重启」两个字段。**
「已判死」是个死状态。写的人知道为什么，读的人不知道。
结果就是：**判死不可逆**——只要当时判错，这条想法就永久报废，没人会再去碰它。
A27 复核 8 条判死，改判了 3 条（M06/M09/M30 从判死改成暂缓），**误杀率 37.5%**。
如果没有那次复核，这 3 条就白死了。

**缺口三：没有「回扫」这个动作。**
做实验是「往前跑」，但**每做完一个实验，都可能让一批旧的判死重新变得有意义**。
比如 A15 面板建好后，分辨力从 ±3.5pp 提到 ±0.4pp——所有「测不动」的判死都该重测。
但没人会在做完 A15 之后自动想起「那 8 条测不动的可以重开了」，除非有一张清单摆在那儿。

## 4. 造了什么

### 4.1 数据源：`research_ledger.json`（41 条）

一条想法 = 一条记录，字段固定 12 个：

| 字段 | 干什么用 |
|---|---|
| `id` / `name` / `kind` | 编号、名字、类型（实验/机制/变量/规则/方案） |
| `status` | 判死 / 暂缓 / 候选 / 采纳 / 作废 / 已完成 |
| `grade` | **判死成色**（A27 立的规矩，见下） |
| `claim` | 这个想法一句话是什么 |
| `tested_by` | 被哪几个实验测过 |
| `evidence` | 证据文件路径（`audit` 会检查文件存不存在） |
| `why_stopped` | **为什么停**（以前完全没有这个字段） |
| `reopen_if` | **什么条件下值得重开**（以前完全没有这个字段） |
| `last_review` | 最后复核日期 |
| `history` | 判决变更史：哪天、谁判的、后来改成什么、为什么 |

覆盖：8 个实验（A16/A17/A18/A20/A22/A24/A25/A27）· 9 个机制 · 5 个变量 ·
14 条入池规则 · 5 条作废方案。

**判死成色七级**（对应 KNOWLEDGE §2.19）：

| 成色 | 含义 | 能不能重开 |
|---|---|---|
| 无信息 | 有没有它都一样，无条件测不出区分度 | 要新证据 |
| 同轴 | 和某个已有变量几乎同一个东西（要写清和谁同轴、那个东西对不对） | 要新证据 |
| 测不动 | 样本/覆盖不够，**是仪器不行，不是它不行** | **能**（等 A15 面板） |
| 弱信号 | 有方向但证据不足 | **能**（换表达形式或大样本） |
| 没测 | 记了结论但根本没跑 | **能**（先补跑） |
| 有害 | 有信息但方向是反的 | 要新证据（可当负向信号用） |
| 收益无改进 | 加了它收益不变 | 要新证据（换目标函数时可能翻盘） |

### 4.2 工具：`tools/ledger.py`（六个命令）

```
py -3.10 tools/ledger.py check  <关键词>   开实验前查：做过吗？判死还是暂缓？为什么？什么条件重启？
py -3.10 tools/ledger.py trace  <id>       一个想法的完整判决史
py -3.10 tools/ledger.py reopen            可重启清单
py -3.10 tools/ledger.py audit             体检（状态/成色矛盾、证据文件、TODO 作废项漏记）
py -3.10 tools/ledger.py stats             按状态/成色计数
py -3.10 tools/ledger.py build             生成 research_committee/想法台账.md
```

`check` 搜的是 `id + name + claim + why_stopped + reopen_if + tested_by` 六个字段，
所以**换个说法也能搜到**——这正是为了绕开「记得住当时的词」这个前提。

`audit` 会主动抓三类问题：
① 状态是「判死」但没写成色（违反 A27 纪律第 5 条）；
② 状态与成色矛盾（比如「判死／测不动」，测不动不是判死）；
③ `TODO.md` 末尾的作废项有没有漏进台账（用 bigram 重合度 ≥0.5 判定，不靠精确匹配）。

### 4.3 三个动作（这才是机制的本体）

**动作一：开实验前，先查。**
新想法上手前跑 `check 关键词`。命中判死/作废 → 先确认重启条件是否满足；不满足就别开。
没命中**也不等于没做过**——`check` 会提醒你再去 grep `DONE.md` 和 `reports/`。

**动作二：实验做完，落档。**
结论写进 `research_ledger.json`，四个字段必填：`status` + `grade` + `why_stopped` + `reopen_if`。
写不出 `reopen_if` 就说明你没想清楚它为什么死——这种情况 `audit` 会给警告。

**动作三：落档之后，回扫（最容易漏的一步）。**
固定问一句：**「这个结论，让哪些旧的判死/暂缓可以重开？」**
有的话就改它们的 `reopen_if` 或状态，并在 `history` 里记一笔。
这一步是「追溯」真正兑现价值的地方——**它是唯一能让旧判决活过来的动作**。

## 5. 为什么这对「项目上限」重要（不只是省时间）

省时间是显然的（不重跑 = 省半天到两天）。但对**上限**的影响更关键，有三个机制：

### 5.1 判死可逆，等于把「已排除空间」重新打开

一个研究项目的上限 ≈ 它能探索的空间大小。**每一次误判都在永久缩小这个空间。**

A27 复核 8 条判死，**改判 3 条**（37.5%）。如果按老办法——判死就是死，没有重启条件——
这 3 条想法就再也不会被碰。而其中 M30 池内收益 +0.129、M06 只是数据缺失 52% 没测全，
**都不是「它不行」，是「我们没测好」**。

台账把「死」变成了「条件性暂停」。这一步本身不产生新收益，但它**把被误杀的空间还回来了**。

### 5.2 改判史本身是元证据：它告诉你「裁判有问题」

`想法台账.md` 末尾有一节「判决变更史」，现在 **6 条改过判**（A20/M04/M05/M06/M09/M30）。

这一节比任何单条结论都值钱：**同一件事在不同时间被判成相反结果，说明当时的判据有问题**。
A27 就是从这 6 条里看出根因的——不是「某个机制错了」，而是**三种判死口径混用**
（信息层 / 增量层 / 收益层），且用错裁判（爆拉标签 vs 收益标签）。

**没有改判史，你会以为那 6 条各自是孤立的技术错误；有了改判史，才看得出是一个系统性问题。**

### 5.3 「测不动」清单是仪器的待办，不是想法的墓志铭

台账里 **8 条「没测」+ 1 条「测不动」**，它们的共同点是：**等 A15 面板**。

这构成了一个非常具体的承诺：A15 建好、分辨力从 ±3.5pp 提到 ±0.4~0.7pp 之后，
这 9 条要**一起重测**（已登记为 TODO 的 A28）。没有这张清单，A15 做完大家只会往前看，
不会回头捞这 9 条——**而它们恰恰是最可能藏着收益的一批**（因为它们是「疑似有用但测不出来」，
不是「测出来没用」）。

## 7. 写进纪律（`AGENTS.md`）

机制不写进规则文件就等于没建。已在 `AGENTS.md` 加一节「想法台账（追溯机制）」，
内容是三条硬约束：

1. **开新实验前必须跑 `check`**，命中判死/作废要先确认重启条件。
2. **实验结论落档时必须写全四字段**（status/grade/why_stopped/reopen_if），跑 `audit` 通过。
3. **落档后必须回扫**，回答「这结论让哪些旧判决可以重开」。

---

## 8. 边界：这个台账不做什么

- **不是 `TODO.md` 的替代**。TODO 放「还没做的」，台账放「已经判过死的」。
  一件事在台账里是「候选」时，它同时应该出现在 TODO 里（TODO 跟踪进度，台账跟踪判决）。
- **不记录没判决的东西**。92 个机制里没测过、也没判过的，在 `变量清单_92机制可算性分级` 里，
  不进台账——否则台账会变成第二份清单，两边打架。
- **`想法台账.md` 是生成物，不要手改**。改 `research_ledger.json`，然后 `build`。

## 9. 我可能错在哪

1. **41 条可能漏了**。我是按 `TODO.md`、`KNOWLEDGE.md` §6、`DONE.md`、`reports/` 反查的，
   如果有人用别的名字记过某个想法，`check` 也搜不到。**发现漏的就补进 JSON，不要另建文档。**
2. **`reopen_if` 有主观性**。「补全资金费率历史后重测」算不算一个真的重启条件？
   我给得比较宽，宁可多写。宽的好处是不误杀，坏处是「16 条可重启」听着比实际乐观。
3. **回扫这一步还是靠人自觉**。脚本能查「暂缓没写重启条件」，但查不出
   「这个新结论应该让某条旧判死重开」——那需要理解，不是匹配。
   **这是本机制最脆的一环，也是唯一真正值钱的一环。**

## 10. 说人话三段

**一句话结论**：以前项目里「这个想法试过没有」只能靠人记得住，现在有一张 41 条的台账，
开工前一条命令能查到「做过、为什么停、什么条件能重开」——A27 复核就发现过去 8 条判死里误杀了 3 条。

**对盯盘意味着什么**：这次不改盯盘方式，也不改任何筛选条件。它影响的是「哪些想法还有机会被捡回来」——
16 条已判死/暂缓的条目带着明确的重启条件挂着，其中 9 条等 A15 面板建好后一起重测。

**下一步与需要用户决定的事**：无需决定。后续所有实验自动按「开前 check / 做完落档 / 落档回扫」三步走。
