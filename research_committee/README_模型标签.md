## 1. 标签规则

| 位置 | 写法 |
|---|---|
| 文件名 | 前缀 `ds4.1f_` 或 `glm5.3f_`（例：`ds4.1f_多倍币捕捉能力突破研究_20261019.md`） |
| 子目录 | 或独立目录 `research_committee/ds4.1f/` |

## 2b. 三个模型的关系（2026-10-19 补充）

`ds4.1f` / `gpt6astra` / `space-bunny` 是**同一任务书下的三个模型独立轮**。

- 按项目规则，**同一件事换模型重做 ≠ 多份独立证据**，三者结论不可简单投票。
- **但各自独立复算出的数字是各自独立的。** space-bunny 的增量是把结论建在
  **归档库实测**之上（`data/archive_raw/` 首根 K 线 + 现有 CSV），
  而非文档转述；其 8 组数字均可用同目录脚本重跑复现。
- 三轮结论**不一致处应视为待裁定的分歧**，例如瓶颈定位：
  ds4.1f 押「排序/持有」，space-bunny 押「选池在前」。见 space-bunny 报告 §1、§六 Q1。

## 3. 为什么 ds4.1f 的文件没有改名

`20261019_verified/shared/constraints.md` 第 23–26 行已按**原文件名**把上述文件列为
"旧 research_committee 草稿，不是来源证据，保留不覆盖"。

因此本轮**只做文件内标注，不改名、不移动**，以免破坏并行代理的路径引用。等该轮收口后，
若需要统一命名，再由主代理一次性迁移，并同步更新 `constraints.md` 的引用。

## 4. 引用时的最小要求

引用本目录任何结论，至少写清三件事：

1. **哪个模型**（`ds4.1f` / `glm5.3f` / 其他）
2. **哪个文件 + 哪个章节**（如 `ds4.1f 报告 §2.1`）
3. **该结论的口径限制**（历史覆盖率 ≠ 交易胜率；事后倍数 ≠ 可实现利润；样本基准率 ≠ 市场基准率）

三条缺一条，就不算可追溯引用。
