# 共享约束（三个研究代理与主代理共同遵守）

日期：2026-10-19。本文件是多倍币捕捉能力突破研究委员会 verified 轮的唯一共享约束；
任务范围与验收见 `../brief.md`。本文件不是研究结论。

## 1. 项目工作定义（派发时必须保留，不得窄化）

- 目标：在活下来的情况下，通过**多次**发现并保留多倍行情利润，提高长期增长上限。
  十倍只是一档，不是硬性下限；翻倍行情同样有研究价值。
- 不许把本项目改造成：通用胜率优化、固定小止盈项目、预设「高上限必然高失败率」的项目。
- 每个建议必须说清它影响「发现 / 进入 / 持有 / 兑现 / 继续参与」中哪个环节，
  减少什么损失，又可能丢掉什么大赢家。答不上来的通用建议不算进展。
- 同币同一波行情的重复观察不能冒充独立命中；也不能为了去重禁止有依据的再次参与。
- 资金参数（本金、仓位、杠杆、损失预算）未定，不替用户指定。

## 2. 本轮边界（硬约束）

- **只读研究**：不修改生产评分、筛选参数、权重；不运行实时扫描；不启动常驻任务；
  不购买数据；不下单；不新建自动任务。
- 现有 A1 实施/互验材料（reports/a1_stage2_*、reports/history_research_review/ 等）
  只读引用为「研究状态证据」，不冒称已通过验收，不向 ds/glm 派活。
- 旧委员会草稿**不是证据来源**，第一轮**禁止阅读**以下文件：
  - `research_committee/part1_现状与瓶颈.md`、`part2a_委员会讨论.md`、`part2b_假设库.md`、
    `part3_社区与反方.md`、`part4_实验与结论.md`
  - `research_committee/多倍币捕捉能力突破研究_研究委员会交付_20261019.md`
  - `research_committee/研究看板.html`
  - `reports/strategy_breakthrough_council_20261019.md`
  - 其他代理的 `raw_output/*` 与 `review_by_*/*`
- 文件归属：每个代理只写自己名下的文件；公共文档、术语表、最终成果只有主代理能改。

## 3. 取证规则

- 涉及项目现状的说法，必须读真实文件，引用格式 `文件路径:行号`；禁止凭名字猜代码。
- 涉及外部人物/社区/跨市场的说法，优先联网取证（WebSearch / WebFetch）：
  记录 URL、作者、发布日期（不明写 unknown）、本轮取得状态、它支持哪句话、不能支持什么。
  网页报错或只有搜索摘要的，不得升级为全文证据。
- 搜索通道不可用或平台需登录时：**明确记录访问缺口**，禁止编造发言、业绩或案例。
- 同一个模型换角色重复同一观点 ≠ 多份独立证据。本轮三个代理是同模型独立上下文，
  交付时必须如实披露这一点。
- 查不到就写「以下为推测，未取证」，不得包装成结论。
- 区分六类结果，互不替代：
  A 历史事件覆盖率提高 / B 固定候选容量下排序质量提高 / C 发现提前量增加 /
  D 进入与持有判断改善 / E 扣费滑点后收益改善 / F 只是模型复杂度或事后解释能力提高。
  任何假设卡必须标注它声称改善的是哪一类。

## 4. 研究卡 schema（每个假设一张卡，字段缺一不可）

```
id: 组前缀-序号（如 AC-1、BF-1、DE-1）
title: 一句话标题
group: A~H 字母 + 组名
kind: regular（常规假设）/ subversive（颠覆性）/ combo（组合）
mechanism: 核心假设与预期机制（哪类参与者、限制或信息差产生机会）
challenge: 它真正挑战或改进了什么（与现有知识的增量）
project_relation: 与现有项目/A1/B1/B3/B10/C3 的关系：复用/扩展/并行/替代
upside: 若成立，可能改变项目上限的方式（对应 A~F 哪类结果）
data: 需要什么数据（现有/本地归档已有/需新源）
decision_time: 以什么时间点作为判断起点
availability: 如何保证只用当时可取得的信息
baseline: 与什么基线比较（随机/简单趋势/现有评分）
experiment: 最低成本验证实验（输入、对照、判据、失败条件）
support: 当前有哪些证据
refute: 什么证据会推翻它；反方如何检验
failure_learning: 失败后能留下什么知识
evidence_ids: 引用编号列表（对应产出文件末尾的证据清单）
result_type: A~F
terms: 用到的项目术语（须在 LEARNING.md 已定义，或列入文末「待新增术语」）
```

所有卡状态一律为**待验证**；结构完整不等于假设成立。

## 5. 语言与可读性（用户硬要求）

- 全程通俗、简洁中文；先说结论和实际影响，再给依据。
- 项目术语（区分度、前视偏差、闸门、洗盘等）使用前先查 `LEARNING.md` 已有定义；
  需要新术语时只在自己产出的文末列「待新增术语」清单，**不改 glossary/terms.yaml**。
- 比喻最多每条一个，且不得暗示已被实测否定的因果（参考 AGENTS.md 3.1 节反例表）。
- 不堆术语、不写营销话术、不用「显著/稳健/有效」下结论；
  差别大就写「大到不像运气」，并给数字。

## 6. 数量要求（第一轮）

- 每个代理产出 **10~14 张机制不同的研究卡**（宁可少而实，不要改名凑数）；
  其中至少 2 张是明确挑战现有框架的（kind: subversive）。
- 每张卡必须有 experiment 和 refute 字段，不接受「可以用机器学习试试」式空话。
- 附「瓶颈定位」一节：你负责的视角认为瓶颈最可能在 A~K 哪几环（可新增类别），
  各给一条证据或反例。
- 文末附「证据清单」（编号、来源、取得状态）与「访问缺口清单」。
