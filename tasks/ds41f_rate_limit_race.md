# ds4.1f：优先修复多路限流交错问题

这是当前采集任务的追加修复，不是启动第二个采集实例。遵守 AGENTS.md、STRATEGY_REVIEW.md 第 1 节、OBSERVATION_PLAN.md 第 11.7 节：保持生存前提下重复捕捉多倍行情、十倍非硬下限、重视启动洗盘；不缩币池或改变策略。

先读 `reports/full_archive_review.md` 末尾“运行巡检与限流交错复现”。主代理已在零网络零磁盘的隔离进程复现：A 请求进行中，B 触发 429；A 返回后仍发校验请求，并在成功结束调用 clear_pause 清掉 B 的未到期暂停。当前真实采集仍推进、日志无 429，不能把潜在错误说成已发生封禁。

请在自己的下载器和测试中修复：

1. 数据、校验和重试请求共享请求前暂停检查，节奏等待之后再检查；已经发出的安全收尾，不能在暂停后新发校验请求。
2. 普通成功结果不能清除其他工作者新登记的暂停。暂停只由到期后指定的恢复探测解除，或采用请求时点/暂停版本比较的等价正确方案；不要一律清空暂停。
3. 已收到归档但暂时不能校验时保留原始字节为待复核，恢复后只补校验，不重下整份；状态和进度不可记完成。
4. 补独立交错测试：另一工作者在归档返回前限流、校验端点限流、晚到成功不解封、重启暂停保持、到期恢复。用事件控制确定顺序，别靠 sleep 碰运气；不联网制造封禁。
5. 先在隔离测试验证，再在块边界安全保存、停止旧唯一进程并替换；不强杀、不手删活进程锁、不并起两个下载器，不更换出口。仅修代码但不更新旧进程内存不算部署完成。

保存修复、测试与切换证据到 `reports/archive_download_ds_full/`；公共文档由主代理入账。回复说明新 PID/版本、已存资料复用、暂停逻辑测试和恢复后采集进度。继续原全量任务，不另做范围调整。
