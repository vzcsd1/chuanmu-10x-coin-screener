## 2. 钉死的口径（主代理裁定，执行者不许改）

### 2.1 时序底账
- 主时段：2022-01-01 ~ 2026-09-30（执行前按可用行与结果成熟时间定稿，不按哪段涨得好挑批次）。
- 查询时钟：固定整点起算的 2 / 3 / 6 小时情景（§9.2）；时钟起点事先定死，不按结果挑整点。
- 可观察市场：每个时点只纳入「当时有数据且满足现货口径」的币；用文件存在推断范围时**显式标注「不等于已证明当年交易资格」**。

### 2.2 前视纪律（r4 bug 守卫，三条硬规则）
1. 评估点只用**已收盘** K 线；历史窗口若已全是收完的 K 线，**不要再机械退一根**（r4 的坑）；以明确的「数据可用时间」对齐，**复用真实评分函数、不只抄 WEIGHTS**。
2. 跨期隔离：选规则用的未来结果窗口**不得跨入验证段**；相邻小时**不许随机打散**进训练/测试。
3. 参考价：信号实际可用之后、下一完整时点的公开价；拿不到就**标缺失**，不回退用信号收盘价、不用事后低点。

### 2.3 事件关联 / 重入（r4 人工重入漏算守卫）
- 同币同规则组持续符合 = **同一事件**，每轮只更新、不加数；再计新事件需「连续 24h 不符合该组 且 距上次事件开始 ≥7 天」；停机 / 缺数据**不算**「不符合」。**由程序自动判定，不许人工挑**。

### 2.4 缺失 / 断更 / 未成熟
- 仅现货、合约部分缺、回退来源**分组记**；未走满观察期 = **未成熟 ≠ 失败**；断更 ≠ 归零（见地基 ①）。

### 2.5 漏选归因六环（主代理口径）
- 每个漏掉的赢家归到**唯一最早失败环**：不可观察 → 数据缺失 → 范围过滤(闸门) → 评分不足 → 排序靠后 → 发现过晚。机械执行**只填客观判据**（卡在哪一环的事实），**归因解释由主代理定**。

### 2.6 地基折扣并入
- 涨幅**同时给 USDT 和 BTC 计价两套**；c_trend 用 **1h 口径**；多空比用**分位口径**；信号区分度**按年读、不取全历史平均**。
