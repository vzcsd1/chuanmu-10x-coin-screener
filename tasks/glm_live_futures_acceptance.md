## 具体工作

1. 跟踪 ui/app.py → 川沐十倍币筛选.py → binance_box_strategy.py 全链。重点：scan 当前只返回过门槛行；合约缺失造成落选的币可能根本没有出现在卡片里。验证“返回卡片合约字段全齐”能否掩盖整轮遗漏，不能只审计页面可见结果。
2. 用实际函数与假接口复现：合约初始化失败、扫描中途被限流、一项字段缺失、真实无合约、上市不足以计算指标、合法数值为零、旧缓存/旧结果、空候选。记录整轮扫描对象、所需字段、已取到字段和前端最终状态；没有证据不得宣称当前 UI 已正确告警。
3. 写最小结果契约建议，区分任务执行完成、数据完整、存在过门槛候选。范围应覆盖进入既有扫描流程且需要合约字段的全部对象；按当前策略所需历史长度与观测时点判断，别任设一个时间阈值。字段名尽量复用已有定义；建议由扫描层提供整轮摘要，不能由前端仅凭 chosen 行猜测。保留不完整结果供查看，但不得标成完整推荐；旧完整结果需标原时间，不能顶替本次成功。
4. 独立核对 ds 请求预算和官方依据，尤其初始化、跨域请求、重试、代理回退、暂停后请求、缓存重启及共享出口不确定性。用反例检验，不照抄 ds 自测；缺陷提供文件行号、离线复现和实操影响。
5. 比较三条最小路线：修现有请求节奏/重复取数、解决已证实的共享出口问题、必要时补同口径数据来源。后两条未证实需要就不实施；分别说明收益、成本、维护、覆盖/时效限制和回退。归档不是实时接口的直接替代，换 IP 不是解除服务方限制的方案。
