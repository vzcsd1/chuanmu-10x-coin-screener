## 共同边界

项目是在生存前提下重复捕捉多倍行情，保留十倍百倍潜力；十倍不是初筛硬下限，高上限不等于高失败率，启动前/启动时洗盘及进入、持有、兑现均重要。不改成通用胜率优化或固定小止盈项目。本轮不缩币池、不提高门槛、不删关键字段、不调整权重。

本轮零真实行情请求：不试扫、不 ping 被暂停接口、不清生产暂停、不换出口绕封、不因期限已到自动联网；可读取官方文档。后台归档继续，不改下载器、状态、并发、出口或进程。动效和候选后续 AI 跟踪均暂缓。测试用假接口和隔离目录，防止 import 或默认参数写入真实 results/。

两人不改公共文档，报告各自落盘后由主代理验收。不得把测试通过写成实时恢复或收益达标。旧报告错误原处划线、注明日期并引用新证据，不静默覆盖。不对正在使用的源码临时回退做测试。

## ds：修请求治理，交出可独立验证的最小补丁

1. 复跑主代理报告三个隔离反例：计数更新未保存、reload 不同步计数、窗口边界双突发。修复真实请求路径，不只修测试直接调用的方法。请求发出前完成额度预约与持久保存；断电可能多算一次可以解释，不能漏算后重复放行。
2. 覆盖两个独立状态实例和真正独立进程的竞争。读取、检查、预约、保存应作为一个不可被另一进程插入的动作；仅在 Python 内存加锁或每人各写 JSON 不算跨进程正确。不创建大型调度服务。额度状态按实际可辨认出口/请求组区分，同时说明共享代理背后其他用户无法被本地计数覆盖，不能保证留余量就不会被他人影响。
3. 明确窗口保证。官方端点 1000/5min 已有证据，跨端点共享范围/窗口类型未明确则标假设。采用能解释并通过边界测试的保守限制，不只改 600/800 常量；本地预算用完等待后继续同轮，不冒充交易所封禁，也不直接交缺字段成功结果。等待结束重查暂停和额度，允许用户中断。不要承诺整轮40秒或单次必不受限。
4. 成功清暂停只能清除自己确认恢复的旧暂停，不能抹掉等待期间或其他请求登记的新期限。用事件控制交错覆盖晚到成功、长短暂停、两个实例重载、到期单次恢复；429/418 经统一出口传播成暂停，后续请求不得发出，保存原错误证据。不得把初始429当普通错误继续另一取数分支。
5. 核对初始化与真实 UI 请求链，保留已有正确修复。正常网络错误和服务方封禁分开；不因本轮修改引入新的隐式绕封路径。
6. 本轮先不加磁盘行情缓存，避免把计数修复和性能扩展混在一起。若现有小时内存缓存不影响本轮正确性就保留；记录缓存后续价值，不以它替代额度保证。不做先OI后LS的大重排，不做无效预筛或历史+快照外推。

验收测试须包含：实际假接口路径预约后重启仍计数；双进程争抢最后额度只允许一个通过；失败请求计数不回退；边界及时间前后跳变不提前释放；等待中被暂停后不请求；正常扫描原范围不变。用假时钟不真等五分钟。已有测试能复用就不另造测试框架。

交 summary.md、可复现证据和 ready_for_glm.md。结论按“已修/未修/需要真实验证”拆分；改正旧报告的单轮必安全、CLI跨整点双突发等过度结论。不得宣布原事故根因已确定。

## glm：修回退计分和整轮完整性，并独立验收 ds

先准备测试与契约，ds 交接后才实施核心接线。可改 binance_box_strategy.py 中回退字段与评分调用处、扫描完整性记录；川沐十倍币筛选.py 的兼容接线；ui/app.py 与 ui/static/app.js、index.html 中必要状态展示；自己的 tests/test_live_futures_acceptance_glm.py 和 reports/live_futures_glm/r2/。不重写 ds 请求治理，不碰 ocean.js、动效/CSS重构或其他代理测试文件。

1. 账户数多空比回退只能展示，不能占 ls_top 参与大户持仓比评分。保留其来源和实际值供解释，正常大户持仓比照常计分。修复是落实现有 C4 语义，不改权重、阈值或其他指标。测试回退不加3分、真实同口径仍加分。
2. 用向后兼容的最小扩展传出整轮摘要；保留已有调用方默认返回约定，避免一次改遍所有入口。摘要覆盖入选、落选、被跳过、失败的原定扫描对象，不从最终卡片反推。合约市场列表取得失败时，“应有合约数”是未知，不能填0并称齐全；真实无合约、历史不足、接口失败与暂停分别记录。

4. 完整性按评分所需字段、观测时点和可计算历史判断，不能仅依赖旧 status=ok。一项新数据不能掩盖另一项陈旧；合法零值不等于请求失败。遇到需要改变指标计算方式的歧义，保存证据、标不完整并报告，不借本轮更改研究口径。不虚构未知指标的统一时效阈值。
5. 用真实函数与假取数跑已有八类情形，再补“可见卡片都齐全、落选币缺数据”和“真空结果全数据完整”。正常完整数据下，除修正回退误计分外，评分/排序/入选集合保持一致。UI测试只能确认同源 mode=demo，使用独立端口；本轮优先注入测试，无须启动真实UI。
6. 独立复核 ds 最终核心版本的额度保存、跨进程、边界和暂停测试，提供接受/返修清单。不把12/12或更多通过数当成修复证据，必须有修复前后的行为对比和具体反例。发现 ds 缺陷时不自行抢改其范围，写精确复现交主代理裁决。
