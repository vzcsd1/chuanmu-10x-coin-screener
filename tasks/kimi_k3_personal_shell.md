## 任务与授权

为现有项目制作一个好看、有趣、自己用的轻量程序外壳。主流程只有：双击启动 → 点击查询 → 等待真实扫描 → 查看标的及入选原因。交付能连接现有 Python 筛选器的可用页面，不只交设计图或静态假数据。用户使用 K3 成本较高：选一个视觉方向直接完成，不生成三套方案、不重复长篇规划、不顺手扩建项目。

项目根目录 `C:/Users/Administrator/Desktop/川沐十倍币筛选`；Windows PowerShell，Python 使用 `py -3.10`。先读 AGENTS.md、TODO.md、DONE.md、KNOWLEDGE.md 的相关章节，再读 STRATEGY_REVIEW.md 第 1、4 节及下列代码。不要扫描 data/ 或 reports/ 全库，不启动、停止或调整 ds 的后台归档下载。

项目区别必须保留：在生存前提下重复捕捉多倍行情，高上限不等于高失败率；十倍百倍是重要目标但不是筛选硬下限，翻倍机会也有价值；重视启动前/启动时洗盘及持有兑现。界面是研究与观察入口，不是交易机器人。不得改变现有评分、权重、门槛或候选池，不做固定小止盈、胜率承诺或十倍币概率预测。“几个标的”不是硬性 Top 3/Top 5 限制，有多少符合就能看到多少。

## 技术取舍：优先轻量且能精细设计

推荐原生 HTML/CSS/JavaScript + Flask 本地薄适配层。沿用现有 Python 环境，新增 Flask 仅列入独立依赖文件；不改原 requirements。运行只绑定 127.0.0.1，不启用 debug/reloader，不提供公网部署或任意脚本执行接口。开发时本地界面不能接受任意跨站调用扫描，状态变更仅用 POST，限制为本地同源请求即可，不做账户系统。

| 选项 | 优点 | 代价与回退 |
|---|---|---|
| 原生页面 + Flask（推荐） | 视觉自由，依赖少，现有 Python 可直接接入 | 多写一点交互；文件集中在 ui/，撤掉不影响 CLI，无框架锁定 |
| Streamlit | 最快形成数据工具 | 定制布局和动效受约束，重运行机制需照顾扫描副作用；更换外壳时重做 UI |
| React/Vite | 组件生态丰富，适合以后大量页面 | 本轮单页收益有限，多一个构建链和依赖维护；未来确有复杂交互才考虑 |
| Electron/Tauri 桌面打包 | 独立窗口与安装体验 | 打包、升级、运行时维护超出当前必要范围；首版不做 |

本次选原生方案；如果仓库当时已存在可用前端，优先复用而非再开一套。无需云服务和付费素材，后续维护以少文件、少依赖为目标；只做个人桌面浏览器使用，基本窄屏适配即可。功能明显增长时再评估换框架，本轮不为假想扩展预埋接口。

## 视觉方向：川沐·观潮

以“个人研究工作台”为主体，加一点观潮意象；副标题可用“寻找值得继续研究的标的”。视觉不是传统交易终端，也不是赌场大屏。

- 建议暖白底、墨蓝文字、青绿主色、少量琥珀色状态点。用留白、字体大小和卡片层次建立质感，拒绝通用紫色渐变模板、满屏霓虹及堆叠大数字。你可以在这一方向内自主优化，不需要征求颜色选择。
- 顶部一幅很轻的自制 SVG 波纹/潮线装饰，与查询按钮构成清楚焦点；装饰不得伪装成价格曲线或行情预测。
- 查询时按钮切换文案、局部波纹轻动，结果按短节奏出现；悬停有细微反馈，复制成功显示短提示。支持减少动态效果偏好，键盘焦点清楚，正文易读。只做必要的 CSS/SVG 动效，不引入动画库或图像生成服务。
- 趣味来自操作反馈和少量自然文案，例如“正在查看市场线索”“这一轮暂未发现符合条件的标的”。不用“百倍神币”“稳赚”“起飞概率”等暗示未证实收益的标签；没有撒花、音效、每日签到、成就系统或吉祥物聊天。
- 默认一套主题做精致即可，不做换肤器。主屏在常见电脑宽度下清楚展示查询区、状态与首批结果；更多结果自然滚动，不强行删掉。

## 第一版功能，仅此范围

1. **查询区**：一个主按钮“查询标的”，短副标题和上次完成时间。首次打开不自动扫市场，刷新页面不重新触发扫描；只有用户点击才开始。显示开始时间与已耗时；真实阶段能取到才显示，无法得到精确总进度时用不确定进度动效，不能编造百分比或扫描币数。
2. **结果区**：默认沿用后端排序。卡片优先展示币名、核心评分/满分、市场范围、合约数据状态，以及两三条真实命中原因。评分是规则得分，不是上涨概率。结果为零就明确空态，不把 CLI 的未达标备用列表当成命中标的，也不偷偷降门槛凑卡片。结果多时仍能浏览全部，可加本地币名搜索，不能后台额外请求行情。
3. **展开详情**：点击卡片在本卡片展开，显示已有的持仓量变化、大户多空比、成交额/市值等少量相关字段及完整命中原因。核心与辅助信息分开，辅助分不参与门槛。无值显示“暂无”，绝不变成 0。指标解释查 LEARNING.md/词表，不另造一套金融解释。首屏别塞几十个指标。
4. **状态与新鲜度**：区别待查询、查询中、成功有结果、成功零结果、失败。正在查询或失败时保留上次成功结果并醒目标注“上次结果”和时间；不能把旧数据冒充本轮实时数据。`deriv_status`、`deriv_as_of` 如实展示；没有整轮数据完整性信息时不宣称全市场检查成功，单币合约缺失不等于无合约或零分证据。原后端已有暂停状态可只读展示，按钮不能绕过它。
5. **复制动作**：复制币名；复制该币的研究提示词，供用户自行粘贴到 Grok/Gemini。提示词要求查公开事件、讨论来源和相反证据，不推断盈利。纯本地生成文本，不接第三方模型、不自动发送数据。浏览器剪贴板不可用时允许手选复制。
6. **保存最后一次结果**：一份轻量本地 JSON 即可，保存原始数值、扫描开始/完成时间与状态。独立放 `results/ui/`；刷新浏览器能恢复界面，失败不覆盖最后成功结果；成功零结果要能正确保存。无需数据库、历史曲线、完整历史查询或导出中心。

本轮不做：登录权限、多用户、云部署、自动下单、资产管理、收益大屏、实时 WebSocket、自动定时扫盘、复杂参数编辑、内嵌 K 线、额外行情接口、归档下载管理、研究实验管理或修改策略。用户本次只是要操作入口；这些都不能作为交付前提。

## 现有代码的真实衔接方式

先精读以下小范围，若代码已更新以实际为准：

- `川沐十倍币筛选.py` 有 `scan(cfg)`，内部调用 `base.connect_exchanges`、`base.public_selection`，最后按 `cfg.min_score` 返回已选标的。使用 `importlib` 按明确路径载入这个模块即可，避免执行 `__main__`。
- `binance_box_strategy.py` 的 `env_config()` 是现有参数入口。保留 `.env`/环境变量及代理、缓存、限流状态路径的既有语义；不要新设一套默认门槛，不改全局工作目录导致缓存另建。
- `binance_box_strategy.py` 的 `run_once()` 返回 chosen，但控制台在零命中时可能展示 ranked 前十。不要解析人类表格或把这个备用展示误当成筛选结果。
- 行对象已含 `symbol`、`score`、`max_score`、`score_kline`、`score_deriv`、`market_scope`、`has_futures`、`deriv_status`、`deriv_as_of`、`conditions`、`extra_score`、`oi_chg_1d`、`oi_chg_3d`、`ls_top`、`market_cap`、`spot_quote_volume`、`percentage_24h` 等。字段不存在则隐藏或标暂无，不另发请求补齐。百分比单位逐项对照 `render_table()`，不要所有字段都乘 100。
- `run_chuanmu.py` 是 runpy 入口，不是现成 Web API。不要从 stdout 抓最后一个大括号来猜 JSON。

薄适配层直接调用原 `scan(base.env_config())`；不复制评分、排序或筛选实现。使用一个后台工作线程执行扫描，前端低频查询本地任务状态；界面打开、轮询状态、展开卡片不触发远端行情查询。只允许一个扫描任务，按钮禁用加后端互斥，多点/刷新不能产生重复请求。状态及错误只围绕这一任务维护，不引入任务队列服务。JSON 输出把 NaN/Infinity 转为 null，中文、负数和合法零值保持正确；外部字段用 textContent 等安全方式渲染。

原扫描函数如果无法提供真实逐币进度，显示“查询中”和已耗时即可；不要为了动效修改策略内部。无法判断整轮合约状态时，按现有字段和可取的状态显示，不虚构整轮覆盖结论。

## K3 的工作节奏与验收

先用不超过 8 行说明选定的视觉布局和文件结构，然后直接完成实现。视觉演示用独立、明确标“演示”的夹具，包含有结果、零结果、合约缺失、查询失败等情况；演示状态不能写入真实结果，也不能默认冒充实时查询。不必联网触发全市场扫描来校对字号。
