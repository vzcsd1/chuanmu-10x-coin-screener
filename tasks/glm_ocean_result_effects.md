## 选定视觉：海中观测玻璃

完整目标是一套连续的材质和动效，不是四个无关特效堆叠。沿用 K3 当前海面配色、光源方向与冷暖关系。主体是透出海面环境感的厚玻璃，边缘偏青白，文字区维持深蓝阅读底；不得把全窗做成一块不透明灰板，也不能透明到字被浪花淹没。

### 1. 主窗口：厚度与水光

- 用内外两层边缘、角部高光和柔和阴影形成有厚度的玻璃轮廓，避免普通发光描边或科幻霓虹框。
- 面板首次出现时，沿边缘掠过一次连续水光，约 0.7—1.0 秒；随后保留低频、可观察但不抢字的光影变化，不一直跑边框灯带。
- 保留原海面作为背景。无需重建海面、不另建一个覆盖全屏的三维场景。玻璃折光可以用视觉模拟，但不得宣称完成了真实物理折射。

### 2. 面板内部：水下流动光斑

- 借鉴光穿过水面在物体上投下的细碎亮纹，放在面板上缘、侧缘或无文字留白区域；这是视觉描述，不新增金融指标。
- 使用自制或已获授权的纹理，或局部低分辨率生成纹理。光斑必须像水光，不能退化为几条正弦曲线、均匀条纹、粒子雨或慢速彩虹渐变。
- 一块主面板共享一个装饰层即可，不为每张卡片创建独立绘制循环。正文保持清楚，不能用对整张卡片应用扭曲滤镜来制造水感。
- 正常模式下持续看约 5 秒能感知变化，不能把透明度调到完全看不见后声称“很高级”；也不以持续闪烁制造存在感。

### 3. 标的卡片：跟随反光与明确反馈

- 鼠标在卡片内移动时，窄而柔和的表面反光跟随位置，离开时自然回落；键盘聚焦给等价的可见边缘反馈，触屏仍可直接操作。
- 卡片可以轻微抬升，但数字、按钮不持续漂浮、不大角度倾斜。不要把高分卡片设计成更猛烈的风暴，视觉强度不代表盈利潜力。
- 复制按钮反馈像一次局部水光脉冲，短促且清晰，不喷泡泡、不制造声音，也不改变原复制逻辑。

### 4. 结果到达与详情展开：连续运动

- 新一轮真实结果首次到达时，主窗口边缘接光，卡片自近到远分组显现；全部首屏卡片约 0.6—0.9 秒进入可读状态，不让大量候选逐张等几十秒。
- `.details` 展开与收起都有连续高度/透明度过渡，像同一玻璃面板内的一层信息被打开，避免突然跳开或整个页面弹跳。
- 重复轮询、输入币名过滤、展开详情和读取旧结果不得重新播放整段入场。以本轮结果身份/完成时间区分新旧；若需 app.js 的最小接线，等 K3 交接后明确标注一处调用，不改 API、排序或数据流。
- 查询中、空结果、失败也用同一套材质；“上次结果”“数据缺失”等状态标签仍清楚。装饰动画不能假装查询进度、行情活跃度或交易成功。

## 技术范围与选择

默认 CSS 伪元素、局部纹理与少量 JS，复用已有变量及已有动画库（如果有）。独立效果模块方便撤换，不新增依赖管理系统、WebGL 海面、网络请求或后台服务。普通玻璃效果虽便宜，但当前已有，不作为主要交付；全窗口液体扭曲代价高且损害阅读，本轮不选。若局部光影确实需要 Canvas，可只使用一个共享低分辨率画布；不要为了实现形式上 WebGL 另建复杂渲染链。

CSS 选择器限定在 #panel / #results 或明确 fx 类，避免污染首页。装饰层 pointer-events:none，不挡滚动、文本选择、复制、搜索与按钮。不要依赖危险的 HTML 注入处理外部数据。

动效暂停跟随现有“静态”按钮及减少动态效果设置，页面在后台时停止无用更新；从后台回来不得加速补播或重复启动循环。K3 海面的接口不清楚时先给最小接入点，不擅自重写 Ocean 模块。性能目标是查询结果出现后不明显拖慢当前海面，报告真实环境和观察到的卡顿，不虚报固定帧率。
