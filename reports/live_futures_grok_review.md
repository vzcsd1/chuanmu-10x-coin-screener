## 结论

核心方向可采纳：按实际接口额度管理请求、复用数据、回退口径不补分、整轮完整性与候选有无分开。但事故归因、替代源排除、双轮时间模型及混合数据建议存在过度推断；不能照单实施。

## 已核对事实

- 官方 Open Interest Statistics 明文 Request Weight=0、IP rate limit 1000 requests/5min。来源：https://developers.binance.com/legacy-docs/derivatives/usds-margined-futures/market-data/rest-api/Open-Interest-Statistics ，查阅 2026-10-07。单页文字不能单独证明多个端点是否共享一个桶；共用本地预算可作为谨慎实现，但应区分实现假设和服务方明确规则。
- 本地 CCXT 4.5.77 的 binance.rateLimit=50，fapiData 所列端点 cost=1；throttle 按 rateLimit×cost 与上一次请求时间比较。它不是所有调用固定耗时 50ms，也不直接表示一整轮耗时。扫描还交错调用现货 K 线并承担网络等待，800×50ms 不能作为真实 40 秒扫描证据。
- binance_box_strategy.py 的 main 在 run_once 完成后 sleep(poll_seconds)。默认 300 秒表示两轮之间至少等待 300 秒，不能凭跨整点推出该单进程 CLI 在同一个五分钟窗口发出两轮请求。UI 快速重查、多个进程、重启、共享出口是另行待核实的情形，不能混用时间模型。
- 本地 reports/live_futures_ds/ 已存在，代码有 DATA_QUOTA_LIMIT=600 等修改。Grok/glm 的“ds 尚未交付”是旧快照，不能代表当前本地版本。
- 回退账户多空比仍写入 ls_top，deriv_score 仅按值判断并给 3 分；标 partial 没有阻止计分。整轮落选/取数失败可从 UI 返回集合消失。这两项报告与现有代码吻合。

## 建议逐项裁定

|---|---|
| “错误接口形态，应换形态” | 目前两条接口本来就提供策略所需历史数据；问题是使用方式和限额治理未充分验证，不证明端点选错。价格推送不能凭空提供大户持仓比。 |

| 先 OI 后 LS 防双突发 | 分两段本身不减少请求或限制速率，必须以统一预算调度。没有必要仅为形态好看重构取数顺序。 |

## ds 新补丁的独立阻塞项

1. note_data_request 更新内存，没有自行 save；实际 call 路径登记后直接 guard.run，正常成功无暂停时没有必然保存。隔离复现：登记一次后目标文件不存在。报告“每请求计数已落盘”不成立。
2. reload 只更新 domains，不同步 data_quota。隔离复现：写方 used=2，读方 reload 后仍 used=1。未见跨进程加锁的读取、预约和写入整体操作，不能以 JSON 文件存在证明多进程共享额度正确。
3. 当前本地固定窗口允许边界双突发：窗口开始为 0，在 299999ms 登记 600 次，300000ms 即返回无需等待；若需要控制任意连续五分钟，其间可能允许再发 600 次。服务方窗口类型未确认前不能承诺这实现满足该保证。应测试边界并选择符合已确认规则的实现，而不是仅改 600 为 800。
4. RequestGuard.run 成功路径仍可 clear 域暂停；需要交错测试判断新暂停是否会被旧请求清除。单线程正常到期成功清除与并发晚到成功不是同一情形。

最小复现（零网络；临时目录自动清理）：

```python
import tempfile
from pathlib import Path
import binance_box_strategy as b
with tempfile.TemporaryDirectory() as d:
    p = Path(d) / 'state.json'
    a = b.RateLimitState.load(p)
    a.note_data_request()
    print('after note file exists:', p.exists())
    a.save()
    c = b.RateLimitState.load(p)
    a.note_data_request()
    a.save()
    c.reload()
    print('writer/reader:', a.data_quota['used'], c.data_quota['used'])
a = b.RateLimitState.load(None)
for _ in range(b.DATA_QUOTA_LIMIT):
    a.note_data_request(now=299999)
print('boundary delay:', a.data_quota_delay_ms(now=300000))
```
