## 1. 这个项目要做什么（原文，不是转述）

项目的自我定义在 `STRATEGY_REVIEW.md` 第 1 节，后续所有文档都以它为约束：

> 通过多次发现并保留多倍行情利润提高长期增长上限，同时不破坏后续参与能力；十倍不是硬性下限。较宽发现范围与有限人工关注并存；研究进入、启动回撤、持有、兑现和机制失效；同波重复观察不能冒充独立命中，也不能用去重禁止有依据的再次参与。不得改成通用胜率优化、固定小止盈或预设高上限必然高失败率。

三条被明确禁止的滑坡（写进了多份文档）：
1. 不得把项目改成"通用高胜率/低波动"策略；
2. 不得用固定小止盈替代"保留大行情"；
3. 不得因为"高上限必然伴随高失败率"就预先降低目标。

同时项目自己承认的边界（`KNOWLEDGE.md` 2.1）：评分尚未被验证为买卖决策依据。

## 2. 当前实际运行的东西（在线链路）

主程序 `binance_box_strategy.py`，约 1,650 行，单文件。执行顺序：

```
connect_exchanges()            # 现货 + 合约分域连接，合约失败可降级为 None
  ↓
public_selection()             # 拉全市场 24h ticker，套三道闸门，截断到 max_symbols
  ↓
对每个候选：取 1h K 线（约 200 根）→ K 线侧评分
            取 OI 历史 + 大户持仓多空比 → 合约侧评分
  ↓
score = kline_score + deriv_score   # 满分 18
  ↓
ranked 排序 → 过滤 score >= min_score(5) → 输出候选
```

### 2.1 评分体系（精确，行号见 A6）

| 键 | 权重 | 判定条件（代码实际写法） |
|---|---:|---|
| `c_trend` | **5** | 收盘价 > EMA50 |
| `oi_chg_1d` | **4** | OI 1 日增速 > **10%** |
| `oi_chg_3d` | **3** | OI 3 日增速 > **20%** |
| `ls_top` | **3** | 大户持仓多空比 < **1.0** |
| `c_breakout` | **2** | 已突破箱体上沿 |
| `c_v24up` | **1** | 24h 成交量 > 前 24h |

**满分 18**（`MAX_SCORE = sum(WEIGHTS.values())`），**门槛 5**。

关键结构性事实（`KNOWLEDGE.md` 2.4 特别强调，因为极易误读）：
- 评分是**相加**的，不是"必须满足某几项"。
- 所以 `oi_chg_1d(4) + c_v24up(1) = 5` 也能进池，**完全不需要趋势**。
- 反过来，`c_trend` 单项 5 分即可单独达标。
- 因此"门槛 5"不等于"至少趋势成立"。这是设计选择，不是数学下限。

### 2.2 三道闸门（与门槛是两回事）

| 闸门 | 默认值 | 环境变量 | 代码注释给出的理由 |
|---|---:|---|---|
| 成交额下限 | **500,000** USDT/24h | `MIN_QUOTE_VOLUME` | 最低档（中位 0.28M）爆拉率 46.2%，明显低于其余档（~60%） |
| 成交额上限 | **50,000,000** USDT/24h | `MAX_QUOTE_VOLUME` | 19 个历史十倍币启动前成交额最大仅 14.87M；上限 50M"只漏 2.7% 的爆拉币、0% 的十倍币" |
| 市值上限 | **2,000,000,000** USD | `MAX_MARKET_CAP` | 按 1% 换手率反推，最大十倍币启动时约 1.5B；取不到市值时不拦（fail-open） |
| 扫描数量上限 | **400** | `MAX_SYMBOLS` | 按成交额排序取前 400 |

另外两个配置：
- `require_okx` 默认 **True**，环境变量 `REQUIRE_OKX`。**注意：该值被读入 Config，但在筛选判断中未被使用。** 详见 §8。
- `require_futures` 默认 **False**。

### 2.3 门槛从 6 降到 5 的实测记录（代码注释原文）

> 6→5 实测：命中率 48.1% → 74.9%，10x+ 命中 9/19 → 15/19，且**样本外精确率不降反升**（测试集 55.9% → 58.2%）。

口径限制：这里的"命中率"指**历史事件在评分上的通过率**，不是交易胜率。出处 `爆拉币命中率与优化空间.md`、`research/12_optimize_gate.py`。【文档记载】

## 4. 已有的量化结论（含口径与限制）

### 4.1 样本基准率

**58.6%**（822 / 1402）。但这个基准率是被设计出来的：对照组（580 个）是从"**曾经爆拉过的币**"里抽的，不是全市场随机抽。所以它**不能**当作全市场的先验爆拉率。

### 4.2 三个被反复验证的信号（`KNOWLEDGE.md` 2.2）

| 信号 | 区分度 | 备注 |
|---|---:|---|
| 收盘 > EMA50 | **+35.3pp** | 最大权重 5 分 |
| OI 1 日增速 | **+12.6pp** | |
| OI 3 日增速 | **+8.9pp** | |
| 大户持仓多空比 < 1 | **+8.0pp** | |

文档原文紧接着写："其余条件基本都是噪音"。

### 4.2b 信号保质期（按年）——**引用时最容易出错的一节**

`reports/foundation_audit_ds/summary.md` 第 36–39 行给出逐年区分度。**两个条件的命运完全不同**：

| 条件 | 2022 | 2023 | 2024 | 2026 | 是否失效 |
|---|---:|---:|---:|---:|---|
| **趋势**（收盘 > EMA50，1h 生产口径） | +21.1pp | — | **+35.8pp（峰值）** | **+29.3pp** | ❌ **没有失效，2026 仍强** |
| **多空比**（分位口径，标准读法） | — | +14.9pp | +17.5pp | **−1.0pp** | ✅ **2026 基本归零** |

> ⚠️ **不要把这两条合并成"核心信号逐年衰减趋近于 0"。**
> 归零的只有**多空比**。趋势 2026 仍有 +29.3pp，只是从 2024 峰值回落。
> 另注：多空比在固定阈值 `<1` 口径下 2026 为 −6.9pp，那是"固定阈值 + 分布漂移"造成的口径假象；**分位口径下的 −1.0pp 才是真实衰减**。

### 4.3 涨幅档与 K 线均分（`KNOWLEDGE.md` 2.3）

| 涨幅档 | 平均 K 线分 |
|---|---:|
| 2–3x | **5.17** |
| 3–5x | **4.67** |
| 10x+ | **4.25** |

即：**涨幅越大，K 线侧平均得分越低**。文档对这个表的原始解读（"找箱体突破这个直觉是错的"）已在 2026-10-05 被部分撤回，改成"表中为组合 K 线分，不能单独证明突破条件无用"。

### 4.4 全底账上的真实发生率（A1 r3 交付）

在**全市场底账**（而非"曾爆拉过的币"抽样）上统计：30 天内出现 ≥2 倍的概率为 **5.15%**。【文档记载，见 `reports/a1_stage2_ds/r3/`】

这一条与 4.1 的 58.6% 口径完全不同，两者不可混用。

### 4.5 评分在"曾爆拉过的币"样本内的表现

- 账面精确率 **72.3%**，基准率 58.6%，**lift = 1.234**。【文档记载】

## 6. 项目自己记录的已知缺陷（编号沿用项目内部编号）

| 编号 | 缺陷 | 影响 |
|---|---|---|

| D-6 | 事件库含**已下架币**（如 ALPACA 45.68x） | 这类样本在实盘当日不可见，历史覆盖率因此偏高 |

| D-9 | 归档库存在畸形文件名 | 采集完整性统计会误报 |
| D-10 | 样本时间分布高度偏斜 | 不同时期的结论不可直接外推 |

D-1 ~ D-3、D-5 来自代码核对；D-4 来自 `research/11_hit_rate_current.py`；D-6 ~ D-10 来自归档库审计（`reports/full_archive_review.md` 及各轮交接报告）。

## 11. 复跑方式（如果研究者需要自己算）

```bash
python research/02_detect_pumps.py      # 生成 pumps.json（事件检测）
python research/03_build_features.py    # 生成 features.csv（启动前特征）
python research/05_deriv_features.py    # 合并合约字段
python research/07_oos_validate.py      # 时间切分样本外验证
python research/08_audit_hindsight.py   # 事后审计（含全市场分母）
python research/11_hit_rate_current.py  # 当前门槛下的历史命中率
python research/12_optimize_gate.py     # 门槛/闸门敏感性
```

事件检测定义（`02_detect_pumps.py`）：低点到高点涨幅 `MIN_GAIN`，窗口内取最低点为 trough、最高点为 peak，`pre_day` 为 ignite 前一日。分档（TIERS）按涨幅切。
